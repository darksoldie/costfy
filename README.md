# COSTFY

COSTFY — MASTER PROMPT

Intelligent Operating System for Digital Businesses

0. INSTRUÇÃO PRINCIPAL

Você está construindo o Costfy, uma plataforma SaaS B2B e B2C voltada para negócios digitais.

O Costfy não deve ser tratado como um simples dashboard, CRM, ferramenta de UTM, BI ou chatbot de IA.

O produto deve ser concebido como um:

Intelligent Operating System for Digital Businesses

A visão do produto é centralizar dados, operações, marketing, vendas, financeiro, tracking, criação, automações e inteligência artificial em uma única plataforma.

O núcleo do sistema é o:

🧠 COSTFY BRAIN

O Brain é a camada de inteligência operacional da plataforma.

Ele deve ser capaz de:

observar;

analisar;

compreender;

contextualizar;

lembrar;

aprender;

recomendar;

planejar;

preparar ações;

solicitar aprovação;

executar ações autorizadas;

verificar resultados;

registrar decisões;

aprender novamente.

A visão de longo prazo é transformar o Costfy em um agente operacional para negócios digitais.

1. PRINCÍPIOS FUNDAMENTAIS DO PRODUTO

O produto deve seguir estes princípios:

1.1 Intelligence first

A inteligência deve estar presente em todo o produto.

1.2 Context first

O sistema deve entender o contexto da página atual.

Se o usuário estiver em uma campanha e perguntar ao Brain:

"Por que ela está performando mal?"

"Ela" deve significar a campanha atual.

Se estiver em um produto:

"Como posso melhorar isso?"

"Isso" deve referir-se ao produto atual.

1.3 Actionable data

Não mostrar dados apenas por mostrar.

Sempre que possível:

Data → interpretação → recomendação → ação.

1.4 Simplicidade

O sistema pode ser extremamente poderoso sem ser visualmente complexo.

1.5 No visual clutter

Informação deve ser organizada hierarquicamente.

1.6 User control

O usuário sempre possui controle final sobre ações de impacto.

1.7 Transparency

O usuário deve saber:

de onde veio o dado;

quando foi atualizado;

como uma métrica foi calculada;

por que o Brain fez uma recomendação;

qual ação será executada;

qual foi o resultado.

1.8 Never fake functionality

Nunca apresentar uma integração, dado, sincronização, IA ou ação como real quando ela ainda não estiver implementada.

Quando uma integração ainda não estiver disponível:

mostrar estado "Not connected";

criar estrutura preparada;

fornecer configuração;

permitir conexão quando credenciais estiverem disponíveis;

não criar dados falsos como se fossem dados reais.
